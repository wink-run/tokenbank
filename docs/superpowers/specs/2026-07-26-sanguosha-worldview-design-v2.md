# Token Bank · 三国杀世界观设计 V2（务实版）

日期: 2026-07-26  
状态: **简化设计 - 聚焦价值**  
反思: 避免生搬硬套，让用户好理解且实际有价值

---

## 0. 设计反思：什么是"生搬硬套"

### ❌ 问题诊断

| 原设计 | 问题 | 用户视角 |
|---|---|---|
| Token → 粮草 | 术语替换无价值 | "为什么要学新词？Token不是更直接？" |
| 100+武将映射表 | 学习成本高 | "我得背诵模型对应哪个武将？" |
| 武力/智力/统帅 | 属性复杂化 | "这些属性和实际性能有什么关系？" |
| 6种阵法 | 只是换名字 | "八卦阵和'本地优先'有什么区别？" |
| 羁绊系统 | 为游戏化而游戏化 | "这和我用AI有什么关系？" |

### ✅ 应该做什么

**核心原则**：
1. **降低理解成本** - 三国元素应该帮助理解，而非增加学习负担
2. **提供实际价值** - 每个三国化元素必须解决实际问题
3. **可选不强制** - 不喜欢三国的用户完全不受影响

## 1. 重新定位：三国杀到底解决什么问题

### 1.1 用户真实痛点

```
痛点1: 模型太多记不住
❌ 方案: 改名为武将
✅ 方案: 用视觉+特征帮助记忆

痛点2: 路由策略难理解
❌ 方案: 改名为阵法
✅ 方案: 用场景化名称降低理解门槛

痛点3: 配置枯燥无趣
❌ 方案: 加成就系统
✅ 方案: 用视觉反馈增加仪式感

痛点4: 社区互动不足
❌ 方案: 加势力联盟
✅ 方案: 用文化认同增强归属感
```

### 1.2 价值锚点

三国杀主题的**唯一**价值：

> **用中国人熟悉的文化符号，降低AI工具的使用门槛，增强归属感。**

不是：
- ❌ 做一个三国游戏
- ❌ 强制用户学习武将对应关系
- ❌ 用游戏化掩盖产品问题

## 2. 简化方案：只保留有价值的部分

### 2.1 核心保留（3个）

#### A. 视觉识别系统

**问题**: 模型列表一片英文，难以快速识别

**方案**: 
```
┌────────────────────────┐
│ Claude Sonnet 4        │  → ┌────────────────────┐
│ Speed: 850ms           │     │ 🎨 诸葛亮风格      │
│ Context: 200K          │     │ Claude Sonnet 4    │
│                        │     │ 擅长: 代码审查、架构│
└────────────────────────┘     │ 速度: ⚡⚡⚡       │
                               └────────────────────┘
```

**价值**: 
- ✅ 视觉图标帮助快速识别
- ✅ "擅长"标签降低选择成本
- ✅ 保留原始模型名，零学习成本

**实现**:
- 不改模型名称
- 仅增加视觉元素（图标、风格）
- "擅长"标签基于实际使用场景

#### B. 场景化路由名称

**问题**: "fallback策略"、"round-robin"难理解

**方案**:
```
❌ 路由策略: Local → Free API → Paid (fallback)
✅ 推荐用法: 
   • 日常办公 - 本地优先，安全省钱
   • 紧急需求 - 速度优先，快速响应
   • 大型任务 - 性能优先，稳定可靠
```

**价值**:
- ✅ 场景化命名降低理解门槛
- ✅ 用户按需求选，不需懂技术
- ✅ 保留技术参数供专业用户查看

**实现**:
- 不删除原有路由配置
- 增加场景化预设
- 可展开查看技术细节

#### C. 使用仪式感

**问题**: API调用冰冷无感

**方案**:
```
调用前:
┌──────────────┐
│ 即将调用      │
│ Claude Sonnet│
│              │
│ [确认调用]   │  → ┌──────────────┐
└──────────────┘     │ 诸葛孔明 领命 │
                     │ [出战]        │
                     └──────────────┘

调用后:
任务完成！        → 此战告捷！
Token: 3500        粮草消耗: 3500
                    诸葛亮不负所托
```

**价值**:
- ✅ 增加情感连接
- ✅ 完成任务有成就感
- ✅ 不影响实际功能

**实现**:
- 调用前简单动效
- 完成后简短反馈
- 可完全关闭

### 2.2 坚决删除（不做）

| 删除内容 | 原因 |
|---|---|
| 强制术语翻译（Token→粮草） | 增加学习成本，无实际价值 |
| 100+武将详细映射表 | 用户不会背，反而困惑 |
| 武力/智力/统帅属性 | 与实际性能指标重复 |
| 阵法详细配置 | 只是路由策略改名 |
| 武将升级系统 | 过度游戏化 |
| 羁绊系统 | 为游戏化而游戏化 |
| 成就系统 | 偏离核心使用 |
| 势力联盟 | 强行社交化 |

### 3.1 Phase 1: 视觉识别（2周）

**目标**: 增加使用仪式感

**任务**:

  - 成功: "此战告捷！XX 不负所托"
  - 失败: "XX 遇阻，正在更换方案..."
  
- [ ] Tray状态显示
  ```
  Token Bank
  今日: 12次出战
  主力: Claude (6次)
  ```

**验收**:
- ✅ 调用有仪式感，不打扰
- ✅ 可完全关闭动效
- ✅ 性能无影响

### 3.4 总计：4周轻量级实现

对比原方案14周，缩减到**4周**，聚焦核心价值。

## 6. 技术实现（简化）

### 6.1 数据结构

```javascript
// 模型配置（不强制映射）
const modelConfig = {
  'claude-sonnet-4': {
    // 原有配置不变
    name: 'claude-sonnet-4',
    provider: 'anthropic',
    
    // 新增视觉辅助（可选）
    visual: {
      icon: 'feather-fan',      // 羽扇图标
      style: 'wise',             // 风格
      color: '#4a90e2',          // 主色
      tags: ['代码审查', '架构']  // 擅长标签
    }
  }
};

// 场景预设（不替代原有路由）
const scenePresets = [
  {
    id: 'daily',
    name: '日常办公',
    icon: '🏠',
    description: '本地优先，安全省钱',
    strategy: ['ollama', 'free-api', 'paid']
  },
  {
    id: 'urgent',
    name: '紧急需求',
    icon: '⚡',
    description: '速度优先，快速响应',
    strategy: ['groq', 'claude', 'local']
  }
];

// 主题配置（极简）
const themeConfig = {
  enabled: false,           // 默认关闭
  showIcons: true,          // 显示图标
  showAnimations: false,    // 关闭动画
  useChineseTerms: false    // 不强制中文术语
};
```

### 6.2 UI适配逻辑

```javascript
// 模型卡片渲染
function renderModelCard(model) {
  const config = modelConfig[model.name];
  const visual = themeConfig.enabled ? config.visual : null;
  
  return `
    <div class="model-card">
      ${visual ? `<div class="icon">${visual.icon}</div>` : ''}
      <h3>${model.name}</h3>
      ${visual?.tags ? `
        <div class="tags">
          擅长: ${visual.tags.join('、')}
        </div>
      ` : ''}
      <div class="metrics">
        速度: ${renderSpeed(model.avgTTFT)}
        成本: ${renderCost(model.costPerToken)}
      </div>
    </div>
  `;
}

// 调用动效（可选）
async function callModel(model, prompt) {
  if (themeConfig.showAnimations) {
    showBriefAnimation(model); // 0.3秒
  }
  
  const result = await actualCallModel(model, prompt);
  
  if (themeConfig.showAnimations) {
    showSuccessMessage(model, result); // 简短反馈
  }
  
  return result;
}
```

## 10. 最终建议

### 10.1 应该做的（核心3件事）

1. **视觉识别** - 图标+标签帮助选择模型
2. **场景预设** - 降低路由配置门槛
3. **微交互** - 适度增加仪式感

### 10.2 不应该做的

1. ❌ 强制术语翻译
2. ❌ 复杂的武将映射体系
3. ❌ 过度游戏化（升级、成就、羁绊）
4. ❌ 强行社交化（势力联盟）

### 10.3 判断标准

> **如果去掉三国元素，产品功能是否受损？**
> 
> - 如果"是" → 说明设计有问题，过度依赖主题
> - 如果"否" → 正确，主题应该是锦上添花

## 11. 总结

原V1方案的问题：
- 🔴 把"三国化"当目的，而非手段
- 🔴 为了三国而三国，生搬硬套
- 🔴 增加学习成本，降低使用效率
- 🔴 过度游戏化，偏离产品定位

V2简化方案的优势：
- ✅ 三国元素作为视觉辅助，不强制
- ✅ 降低理解门槛，提升选择效率
- ✅ 专业用户完全不受影响
- ✅ 4周快速验证，成本可控

**核心理念**：
> 不是做"三国杀版Token Bank"，  
> 而是给Token Bank加一点点中国风的视觉温度。
