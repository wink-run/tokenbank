# 公开网页信息架构：两类用户

> 范围：tokenbank.wink.run 上不安装客户端也能打开的页面。
> 原则：只有两类用户——**普通用户**和**开发者**。每个页面只服务其中一类，顶部用「用智能体 / 开发者」切换。

## 1. 两类用户

| | 普通用户 | 开发者 |
|---|---|---|
| 是谁 | 有个活要干、不想折腾的人 | 做智能体、同时用好几个 runtime 和模型来源的人 |
| 关心什么 | 智能体能不能帮我把事办成，像打车一样省心 | ① 统一管理自己的 runtime（Pi、Claude Code、Cursor…）和模型供应商，界面和接口都要 ② 把智能体分享出去：自己随处用、分摊费用、和别人协作 ③ 从市场获取模型、Skill、智能体模板，自用或加工后上架给普通用户 |
| 不关心什么 | runtime、模型名、Token、积分怎么算 | 不需要被教育「什么是智能体」 |
| 怎么用 | 浏览器 / 手机打开，未登录可试一轮，登录后多轮、按次扣积分 | 装客户端；接口走本机网关 |

两类用户靠「上架」连起来：开发者把智能体上架到广场，普通用户在广场使用，每次使用给开发者结算积分。

```
开发者：资源市场 ─获取→ 加工 ─→ 统一管理（纳管到 runtime，接口调试）─→ 分享与收益（自己 / 圈子 / 公开）
                                                                                  │ 上架
普通用户：                                                         智能体广场 ◀────┘  像打车一样用
                                                                       │
                                                         每次使用结算积分 → 分摊开发者的订阅和算力
```

## 2. 页面

| 页面 | 地址 | 用户 | 一句话 | 主要内容 |
|---|---|---|---|---|
| 智能体广场 | `/agents` | 普通用户 | 别人调好的智能体，打开就能用 | 只有智能体（全部 / 在线）；打车式、手机浏览器就能用、一个链接拉朋友；和通用助手的对比 |
| 开发者概览 | `/dev`（新） | 开发者 | 你的智能体和模型，管起来、分出去、再赚回来 | 三件事入口；获取 → 加工 → 管理 → 上架 → 普通用户使用的循环；统一接口一览；网络实时数字 |
| 统一管理 | `/harness` | 开发者 ① | 智能体平台再多，一个入口全管起来 | runtime（三种接入方式）和模型供应商；省掉的四件事；主 Agent 按特点派活；统一接口示例 |
| 分享与收益 | `/network` | 开发者 ② | 调好的智能体和闲置额度，自己随处用，别人用你来赚 | 模型 / 智能体两类分享；三步上架；只给自己（一人圈子）/ 圈子 / 公开；配方不外泄；排行与在线供给 |
| 资源市场 | `/market`（新，含圈子） | 开发者 ③ | 别人做好的，拿来就用，改改就能上架 | 模型 / Skill / 智能体模板 / 提示词 / 场景与插件；自用、加工、上架三条路 |
| 管理圈子 | `/circles` | 开发者（普通用户经邀请链接进入） | 圈子是资源市场的一种可见范围 | 创建、邀请码加入、审批、圈子详情；不在导航里，从资源市场「管理圈子」进入 |

导航：
- 普通用户页：`用智能体 | 开发者` 切换。
- 开发者页：切换 + 二级导航 `概览 · 统一管理 · 分享与收益 · 资源市场（可见范围：公开 / 我的圈子）`（窄屏放在首屏顶部横滑）。
- 广场和开发者概览的页尾有「你是哪一类用户？」两张卡；开发者各页页尾有「开发者的三件事」。

旧地址：`/agents#models` → `/market#models`，`/agents#resources` → `/market#skills`，`/network#models|agents|resources` → `/agents#…`（再按上条转到市场），`/network#circles` → `/circles`，`/tools` → `/agents`。

## 3. 从代码确认过、页面可以承诺的事

| 承诺 | 依据 |
|---|---|
| 智能体同一个接口，只换 `harness_id` | 本机网关 `POST /v1/agent/responses`；本机 `pi` / `claude-code` / `codex` / `cursor` / `kimi-code`，社区 `community:<id>@<用户名>` |
| 模型原生名不变、协议互通 | 网关 `/v1/chat/completions`、`/v1/messages`、`/v1/responses` |
| 约 20 个应用可纳管 / 还原 | `client/electron/config/app-handlers.yaml` |
| 未登录可试一轮、多人接龙同一场对话 | `agent-landing.html` |
| Skill / 提示词 / 智能体模板一键纳管并投射 | 社区目录 `/api/community-catalog`（type: skill / prompt / assistant） |
| 只给自己 | 建一个只有自己的圈子，范围选它 |
| 局域网算力对外服务（作为一个特点写进分发层、上架路线、对比表和分享卡片，不单列板块）：有公网 IP 直连网关，没有则经 Token Bank 中转 | 直连：CLI / Docker 网关 `GATEWAY_BIND_HOST=0.0.0.0`（docker-compose 默认），`:11430` 网关 Key 鉴权；中转：节点出站 WebSocket 连接云端，无需入站端口（README「可贡献算力」） |
| Key、Skill 不出本机，任务在分享者设备执行 | 供给与雇佣链路 |

## 5. 和谁比、怎么比

| 用户 | 对比对象 | 我们的说法 | 放在哪 |
|---|---|---|---|
| 普通用户 | Claude、WorkBuddy 等自己开订阅的产品（它们同样有手机、桌面、网页版，所以「随手就用」不是差异） | **买车不如打车** + **各家能力一个入口**（广场上的智能体跑在不同引擎和模型上，一个账号一份积分通用）：拿到手（注册、订阅、地区和支付限制 vs 浏览器打开先试一轮）、学会用、花多少（包月 vs 按次）、够不够灵活（一家能力 vs 每件事挑最合适的）、稀缺能力、和朋友一起 | `/agents` |
| 开发者 | 纯模型网关 / 切换工具（页面上不点名具体产品） | **模型网关是一层，这里是一座智能体应用工厂**：运行时、模型、资产、接口、观测、分发六层现成，可以在上面架应用（接口做进产品 / 上架即得网页应用 / 接入已有应用）；管整套智能体（runtime + 模型 + 资产），模型和智能体一套接口，有 Trace / 盘点等看板，有主 Agent 调度，管完还能分享和获取 | `/harness`（完整对比表）、`/dev`（三点摘要） |

## 6. 首页特点放到哪一页

| 首页特点 | 归属 | 页面上的位置 |
|---|---|---|
| 智能体纳管、一键换模型、场景路由、Trace 管理、资产管理、用量看板、跨端归集、智能体编排 | 开发者 · 统一管理 | `/harness` 逐项展开（编号 01–08，每项有锚点 `#f-onboard` 等、真实截图或示意图）；`/dev`「统一管理里有什么」8 张卡直达各项 |
| 开源、不改使用习惯、随时还原、三平台 | 开发者 | `/dev`、`/harness` 首屏承诺 |
| 闲置赚钱、Key 与 Skill 不出本机、跨模型兑换、时间价值平移、供给排行 | 开发者 · 分享与收益 | `/network` |
| 社区目录（MCP / Skill / Prompt / Agent） | 开发者 · 资源市场 | `/market` |
| 好模型用不起 → 按次用稀有模型和专家智能体 | 普通用户 | `/agents`「买车不如打车」 |

普通用户的手机 App 在规划中；当前页面写「手机 App 正在路上，现在用网页就行」。

## 7. 文案原则

- 普通用户页不出现 runtime、Token、积分计算、模型表；开发者页不讲「打车」。
- 只写代码里已有的能力；数字来自接口实时数据。
- 点名 Claude、Grok、WorkBuddy 只用于说明「单人自配」这类产品形态。
