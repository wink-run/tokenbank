# 公开网页信息架构：用户、关系与页面

> 范围：tokenbank.wink.run 上不需要安装客户端就能看到的页面（`/agents`、`/harness`、`/network`、`/circles`，以及它们链接的 `/a/`、`/m/`、`/u/`）。
> 目的：把「用的人」「管的人」「供给的人」「组局的人」分开讲清楚，各自一页，同时让一个人在几个角色之间自然升级。

## 1. 产品里实际有什么（网页能讲的事实）

| 能力 | 在哪里实现 | 网页可以承诺什么 |
|---|---|---|
| 社区智能体网页对话 | `/a/{id}`（agent-landing.html） | 未登录可试一轮；登录后多轮，按次扣积分；任务在分享者设备上执行 |
| 多人接龙同一场对话 | `/a/{id}?share=` | 分享链接后大家按时间接在同一条对话里；历史分「我发起 / 我参与」 |
| 社区模型网页试用 | `/m/{model}` | 文本对话、生图；嵌入模型只有 API |
| 统一智能体接口 | 本机网关 `POST /v1/agent/responses`，`metadata.harness_id` | 本机应用用 `claude-code` / `codex` / `cursor` / `kimi-code` / `pi`，社区智能体用 `community:<id>@<用户名>`，同一个请求体 |
| 统一模型接口 | 本机网关 `/v1/chat/completions`、`/v1/messages`、`/v1/responses` | 原生模型名不变，协议自动转换，按应用绑定路由 |
| 一键纳管 / 还原 | app-handlers.yaml（约 20 个应用） | Claude Code、Codex、Cursor、WorkBuddy、Kimi Code、OpenClaw、OpenCode、Hermes、Pi、Trae、Copilot、Qwen、Grok…… |
| 主 Agent 派发 | 游乐场 + `tokenbank-agent-bridge` MCP | 主 Agent 接任务，按特点派给已纳管或已雇佣的智能体 |
| 资产投射 | 资产页 | MCP / Skill / Prompt 一处纳管，投射到已纳管且已安装的应用 |
| 供给 | 交易 → 上架供给 | 模型额度、本地 / 内网模型、已投射智能体、已安装应用；范围公开或指定圈子；出站连接无需开端口；Key / Skill 不出本机 |
| 积分 | 结算器 | 被调用即赚；贡献率 > 消费率；圈子可共享 |
| 圈子 | `/circles`、`/c/{id}` | 圈内资源只对成员开放；邀请码 / 邀请链接；邀请双方得积分 |

## 2. 用户：按「带来什么、想要什么」分

一个人通常同时是好几种角色。按场景分比按人分更准确。

| 角色 | 典型的人 | 他带来 | 他想要 | 最怕 | 在网页上的入口 |
|---|---|---|---|---|---|
| **使用者** | 不想折腾的普通用户、临时有活的人 | 一个任务、几点积分 | 马上把事办成，不用买 Key、装环境、写提示词 | 配置门槛、包月浪费、不知道选哪个 | 广场 `/agents` → `/a/`、`/m/` |
| **驾驭者** | 同时装了 Claude Code、Codex、Cursor、WorkBuddy… 的重度用户和开发者 | 一堆智能体平台和订阅 | 一处管起来；统一接口；按特点派活；人在外面也能用自己那台 | 配置各管各、资产散落、账单不明、每个平台接口都不一样 | OneHarness `/harness` |
| **模型供给者** | 有闲置订阅、本地 Ollama、内网私有模型的人 | Token 和算力 | 闲着的额度变积分，抵扣自己的开销 | Key 泄露、要开端口、被白嫖 | 共享网络 `/network`（模型那一栏） |
| **智能体创作者** | 调教出好用智能体或 Skill 的人 | 专业能力（提示词、Skill、工具链） | 被更多人用、被看见、有回报 | 配方被抄走 | 共享网络 `/network`（智能体那一栏）、主页 `/u/` |
| **组局者** | 团队负责人、朋友圈里的「技术担当」 | 一群信任的人 | 只给自己人用、一起分摊、一起玩 | 外人进来、成员看不到圈内资源 | 圈子 `/circles` |

### 模型和智能体的关系

- 模型是**原料**：按 Token 计价，看延迟、节点数、模态。
- 智能体是**成品**：模型 + 运行时（Claude Code / Codex 这类 harness）+ Skill / 工具链 + 调教经验，按次计价，看能不能把事办成。
- OneHarness 让智能体像模型一样可替换：换一个 `harness_id` 就换一个智能体，和换一个模型名一样简单。所以页面上两者并列，但讲法不同：模型讲「快不快、全不全」，智能体讲「谁调的、擅长什么」。

## 3. 关系：一个飞轮，四条升级路径

```
          ┌──────────── 带朋友来（分享链接 / 邀请码）────────────┐
          ▼                                                     │
   使用者（网页试用）──装客户端，把雇来的智能体接进自己的工具──▶ 驾驭者
          ▲                                                     │
          │                                      有闲置额度 / 调出好用的智能体
   广场更丰富 ◀───────── 上架（公开或圈子）◀───────── 供给者（模型 / 智能体）
                                                                │
                                         只想给自己人用 ──▶ 组局者（圈子）
```

- 使用者 → 驾驭者：在网页上用顺手了，装客户端，雇佣的智能体直接出现在游乐场和 Claude Code 等应用里。
- 驾驭者 → 供给者：纳管后看得到自己哪些额度闲着、哪个智能体好用，顺手上架。
- 供给者 → 组局者：不想公开，就建圈子只给自己人。
- 组局者 → 使用者：一个链接把朋友拉进来，从使用者开始。

页面要做的事：**每页只服务一个角色，但在页尾给出下一步**。

## 4. 页面结构

| 页面 | 地址 | 服务角色 | 一句话 | 主要内容 |
|---|---|---|---|---|
| 智能体广场 | `/agents` | 使用者 | 别人调好的智能体和模型，打开就用 | 智能体 / 模型 / 技能与场景 三个页签；打车式、接进自己工具、一个链接拉人；和通用助手的对比 |
| OneHarness | `/harness`（新） | 驾驭者 | 智能体平台再多，一个入口全管起来 | 支持的应用墙；一处纳管 / 资产投射 / 按特点派活 / 各终端随处用；统一接口示例（本机应用、社区智能体、模型同一套） |
| 共享网络 | `/network` | 模型供给者、智能体创作者 | 闲置的额度和智能体，让别人用，你来赚 | 实时网络；分两栏讲「分享模型」和「分享智能体」各自关心什么；三步上架；公开 / 圈子；配方不外泄；排行与在线供给 |
| 圈子 | `/circles` | 组局者（也服务使用者加入） | 和信任的人一起用 | 我想用 / 我想分享 两张入口卡；我的圈子；发现公开圈子 |

四页共用顶部导航：**广场 · OneHarness · 共享网络 · 圈子**；广场、OneHarness、共享网络三页页尾共用一条「你是哪种用户」导引，指向另外几页。

旧地址：`/network#models|agents|resources` 跳到 `/agents#…`，`/network#circles` 跳到 `/circles`，`/tools` 仍跳到 `/agents`。

## 5. 文案原则

- 每页开头一句话只回答这个角色最关心的事，不混入别的角色的卖点（例如广场不讲赚积分，共享网络不讲打车）。
- 只承诺代码里已经有的能力；数字用接口里的实时数据，不写估算值。
- 点名 Claude、Grok、WorkBuddy 只用于说明「单人自配」这类产品形态，不评价具体产品好坏。
