## 二、准备两台真机

**服务端**：照常部署就行，设备网络和官方中继开箱即用（后端内置 `/mesh/ws`，中继地址按域名自动下发）。部署后检查：

```bash
curl https://<域名>/mesh/relay/healthz
```

应该看到 `"enabled": true`、`"issuer_keys": 1`。可选变量见仓库根目录 `DEPLOY.md`「设备网络」。

**设备**：A（比如笔记本）、B（比如台式机 / Mac mini），同一个 TokenBank 账号登录，客户端都指向上面的测试服务端。B 上装好至少一个命令行智能体（Claude Code 或 Codex），最好也配一个本地模型（Ollama）。B 上准备一个 git 仓库。测中继时再加第三台 C（另一台电脑，放在别的网络里，比如连手机热点）。

设备之间用 TCP 41750 端口（入口），局域网发现用 UDP 41700。防火墙要放行。

每台的智能体 Key 在 `~/.llm-agent/local-config.json` 的 `agent_api_key`，下面的 `curl` 里写成 `$KEY`，网关默认 `http://127.0.0.1:11430`。

## 三、入网（E1）

| # | 怎么做 | 应该看到 |
|---|---|---|
| 3.1 | 两台都登录。打开「盘点」，选中「这台电脑」 | 「改名」下面一行有「设备网络」开关，旁边写「打开后自动领设备证书…」 |
| 3.2 | 先在 A 上打开「设备网络」 | 几秒后出现「已和云端同步」；接活、同时接、开放本机模型、中继、工作区几个设置出现 |
| 3.2a | 再在 B 上打开 | B 显示「这是新设备：在一台已经入网的设备上批准后…」；A 的设置条上方出现「新设备「B」想加入我的设备网络」 |
| 3.2b | 在 A 上点「批准」 | 十几秒内 B 自动入网，A 那条提示消失；两台互相看到。点「拒绝」则 B 一直等着 |
| 3.3 | 网关页、模型页、游乐场 | 多出「所在设备」列 / 设备标签，能看到对方设备的名字（见第五节） |
| 3.4 | `curl -H "Authorization: Bearer $KEY" localhost:11430/v1/devices` | 两台都在，对方 `online: true`，`connection` 是 `direct`（同一局域网）|
| 3.5 | 一台退出登录 | 那台的设备网络停止，另一台看到它离线 |
| 3.6 | 重新登录 | 自动重新入网，不用再点开关 |
| 3.7 | 在「个人页」的设备列表里删除 B | 1 分钟内 A 断开 B（A 日志 `已被吊销，断开`），B 再也连不上 A |
| 3.8 | 删除后 B 重新登录、重新打开设备网络 | B 重新注册，又要 A 批准一次，批准后恢复正常 |
| 3.9 | 用**另一个账号**登录第三台设备并打开设备网络（同一局域网） | 它看不到前两台，前两台日志里有 `other_user` |

## 四、统一入口（E2）

**模型**

| # | 怎么做 | 应该看到 |
|---|---|---|
| 4.1 | B：盘点 → 本机 → 打开「开放本机模型」 | A 的「模型 · 账户」里出现一行「B 的模型源 · 其他设备开放的」，所在设备标 B |
| 4.2 | A 上没有、B 上有的模型（比如 Ollama 的 `qwen3:8b`），在 A 的游乐场「模型对话」里用 | 由 B 回答；A 网关页「路由」明细里这条标着 B |
| 4.3 | A 和 B 都有同一个模型 | 先用 A 本机的；把 A 那个源停掉后自动换到 B |
| 4.4 | 指定设备：模型名写 `mine:<B 的名字>/<模型>` | 一定在 B 上做 |
| 4.5 | B 关掉「开放本机模型」 | A 的账户表里那行消失，4.2 改为报找不到模型 |
| 4.6 | B 的路由明细 | 从 A 来的请求，详情里「发起设备」是 A |

**智能体**

| # | 怎么做 | 应该看到 |
|---|---|---|
| 4.7 | `curl -H "Authorization: Bearer $KEY" -H 'content-type: application/json' localhost:11430/v1/agent/responses -d '{"input":"看看仓库里有什么","metadata":{"harness_id":"mine:claude-code@<B 的名字>","workspace":"<B 的工作区名>"}}'` | 在 B 的那个仓库里执行，结果回到 A，任务号是 `mesh:<B>:…` |
| 4.8 | A 的游乐场「智能体路由」输入 `/claude-code@<B 的名字> 看看仓库` | 跳过主智能体，直接在 B 上做；路由明细显示「指定」和 B |
| 4.9 | 盘点里给 B 改名（比如 `studio`） | 交易页「设备名称」同步变成 studio；之后 `@studio` 能派活，原来的电脑名也还能用 |
| 4.10 | B 关掉「接我其他设备派来的活」 | A 上 B 的应用、智能体消失；派给 B 的活报「没有…」 |
| 4.11 | B 的「同时接」设成 1，A 同时派两个慢任务给 B | 第二个立刻返回「这台设备正在跑 1 个任务，满了」（429） |

## 六、主智能体派活（E4）

前提：A 上游乐场「智能体路由」能用（主智能体是 Claude Code 或 Codex）。

| # | 怎么做 | 应该看到 |
|---|---|---|
| 6.1 | 智能体路由里给一个能拆开的任务，比如「给登录页加记住我，同时写接口文档、补单测」 | 主智能体把互不依赖的子任务用 `background` 并行派出（可以派到 B） |
| 6.2 | `GET /v1/agent/responses/<主任务号>?tree=1` | 整棵任务树，B 上的子任务标着 `mesh_device` |
| 6.3 | 同时续同一个子任务两次（`previous_response_id` 相同） | 第二个返回 409「已经有一轮在接着它做」 |
| 6.4 | 网关 · 路由明细里点一条子任务 | 详情里有「父任务」；派到 B 的有「路径」（局域网直连 / 经某台中继 / 经官方中继） |

MCP 工具（主智能体自己会用，也可以在 Claude Code 里手动调）：`tb_list_agents`（列出 `mine:…@设备`）、`tb_dispatch_agent`（`background`、`previous_task_id`）、`tb_task_status`（`wait: any/all`）。

## 八、中继（需要你的网络环境）

设备之间连不上时：先经我名下能被连到的设备中继，没有再经 TokenBank 官方中继。两种中继都只看到密文。

**我的设备当中继**：B 要能从外面连到。有公网 IP，或者在路由器上把 TCP 41750 映射到 B；映射后可以在 B 的 `~/.tokenbank/mesh/config.json` 里写 `"public_addr": "<公网IP>:41750"`。

| # | 怎么做 | 应该看到 |
|---|---|---|
| 8.1 | B 准备好后等一两分钟（云端回拨验证） | B 的设置条「给其他设备当中继：自动」；A 的 `/v1/devices` 里 B 的 `relay.verified: true` |
| 8.2 | C 放在别的网络（手机热点），登录同账号、批准入网 | A、C 互相在线；`/v1/devices` 里对方 `connection: "relay"`、`via.label` 是 B；所在设备标签后面写「· 经 B」 |
| 8.3 | 在 A 上调只有 C 有的模型 / 派活给 C | 照常完成；路由明细「路径」写「经「B」中继」 |
| 8.4 | 盘点页设备胶囊 | B 上标「中继 · 1」（正在转发 A↔C）；B 的设置条写「正在转发 1 对设备」 |
| 8.5 | 在任意一台把「中继」改成「官方中继」（要服务端配了 `MESH_RELAY_URLS`） | 所有设备跟着换：标签变「· 经官方中继」，B 的「中继」标记消失 |
| 8.6 | 改回「自动」，然后把 B 关机 | A、C 半分钟内回落到官方中继，功能照常 |
| 8.7 | 「中继」下拉里手动选 B，再把 B 的「给其他设备当中继」关掉 | 设置条提示「指定的设备不可用，暂用官方中继」 |

**官方中继**：后端内置，部署后就有（`curl https://<域名>/mesh/relay/healthz` 看 `"enabled": true`）。服务端没改过设置的话这里不用做什么。

## 九、雇佣走设备通道

前提：后端已部署（内置官方中继）。两个账号：你的 A，另一个账号的出租机 R（开着出租、出租一个命令行智能体、开着设备网络）。

| # | 怎么做 | 应该看到 |
|---|---|---|
| 9.1 | R 开出租 | R 的日志 `[agent] register caps=agents,mesh_hire` |
| 9.2 | A 在交易页雇 R 的智能体，在游乐场用它做一件事 | 照常完成；R 日志 `[mesh] 接到雇佣 at-…（…，经设备通道）` |
| 9.3 | 两边的积分 | A −5，R +5，和以前一样 |
| 9.4 | A 中途叫停 | A 退回 5 分；R 停掉进程、不加分 |
| 9.5 | R 关掉设备网络（或用旧版客户端）后再雇 | 照样完成，R 日志里没有「经设备通道」（走云端转发） |
| 9.6 | 网页上雇同一个智能体 | 照常（网页还走云端转发） |

## 已知限制

- 两台都在 NAT 后面、又没有能当中继的设备时，要经官方中继（没做打洞）。
- 其他设备开放的模型源只在降级链里自动用；要钉某台设备，模型名写 `mine:<设备>/<模型>`。
- 签发方公钥现在随证书从云端下发；正式版要内置进客户端。
- 桌面版签名公证没在 macOS / Windows 上验证，桌面版先用开发模式（`npm run dev`）测。
- 网页、访客、分享对话的雇佣还走云端转发。
- 不做：圈子成员互派、手机当执行节点、消息注入你正在用的会话、完全不连云端的局域网模式（E6，以后再做）。
